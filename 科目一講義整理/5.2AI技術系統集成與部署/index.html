01｜從模型到業務服務

官方 P. 5-14～5-22

AI 部署不只是把模型檔放上伺服器，而是涵蓋資料管線、服務介面、安全權限、企業流程、監控、回訓與優化的完整生命週期。

資料來源倉儲、湖、IoT、第三方
資料管線擷取、轉換、清理與入庫
AI 模型訓練、驗證與版本
API 服務推論、認證、限流與快取
業務系統ERP、CRM、POS、MES、App
監控回饋指標、日誌、告警與人工回饋
持續更新再訓練、驗證、安全部署

架構主線

模型 × 資料 × 企業系統 × API × 使用者介面 × 安全機制

02｜五個系統集成面向

官方 P. 5-14～5-16
面向核心工作典型技術／系統
資料管線整合持續擷取、格式轉換、清理、驗證、入庫與供應模型。Data Warehouse、Data Lake、IoT、API、ETL／ELT。
企業系統整合讓模型結果回到日常流程，觸發實際作業。ERP、CRM、POS、MES。
API 與平台接軌把推論封裝成網站、App、BI 或其他服務可呼叫的介面。RESTful API、gRPC、Webhooks、API Gateway。
安全與權限認證、授權、角色權限、流量控管、日誌與稽核。OAuth 2.0、JWT、RBAC、API Gateway、Log。
跨雲與異質整合協調地端、不同雲端與邊緣的資料同步、服務調用及狀態。AWS、Azure、Edge AI、Service Mesh。

系統集成的價值

消除資料孤島、打通既有系統、服務化推論、直接驅動流程，並讓安全與跨平台治理貫穿全程。

API 層不只轉送請求

還需處理認證、速率限制、快取、逾時、重試、容錯、版本、日誌與負載管理。

03｜穩定、可擴充的架構設計

官方 P. 5-16～5-17
μSVC

微服務

每個服務聚焦單一功能，可獨立開發、更新與擴展；錯誤較易隔離，但分散式介接與管理更複雜。

BOX

容器化與編排

Docker 封裝應用與依賴；Kubernetes 負責調度、擴縮、健康檢查、故障恢復與版本更新。

API

模型服務化

用 Flask、FastAPI、TensorFlow Serving 等把模型封裝為推論服務，加入版本、安全、Log 與 Metrics。

HA

高可用與擴充

以冗餘、Failover、Load Balancing、Autoscaling 避免單點故障並承接流量變化。

機制用途考點
Rolling Update逐批替換執行中的版本。降低更新造成的服務中斷。
Autoscaling依流量或資源使用自動增減節點。處理高低峰、控制資源成本。
Load Balancing把請求分散到多個推論節點。避免單一節點過載。
Redundancy部署多個可替代節點。降低單點故障。
Failover主節點故障後切換到備援。維持服務連續性。
Circuit Breaker外部服務異常時暫停呼叫並快速失敗／提供替代。防止延遲擴散成 Cascading Failure。iSpan 補充

完整架構流程

模型 → API → 容器 → Kubernetes → 負載平衡／自動擴縮 → 監控與故障恢復

04｜四種部署模式

官方 P. 5-17～5-18
模式優勢適用情境主要挑戰
公有雲彈性擴充、快速部署、全球節點、按量付費、GPU 易取得。新創、跨區域、GPU 密集訓練與快速擴展。資料主權、法規、長期成本與供應商鎖定。
私有雲控制性、資料掌握與客製安全較高。政府、金融、醫療與高度敏感資料。建置維運成本高，資源彈性較有限。
邊緣運算低延遲、即時、節省頻寬、資料較少外傳。工業設備、智慧城市、車聯網、手機與 IoT。裝置算力有限，模型更新與同步較難。
混合部署依任務兼顧算力、速度、安全與彈性。雲端訓練、私有環境保存敏感資料、Edge 即時推論。整合、同步、一致性與監控複雜。

選擇順序

資料敏感度 → 延遲需求 → 運算需求 → 成本 → 擴充需求 → 法規要求

快速擴展選公有雲；高度控管選私有雲；即時低延遲選 Edge；需求混合則採 Hybrid。

05｜MLOps、CI/CD 與模型監控

官方 P. 5-18～5-20

MLOps 是 DevOps 在機器學習領域的延伸，將開發、訓練、測試、部署、監控與更新串成自動化、可追蹤、可重現的流程。

機制核心功能主要目的
CI程式碼或資料變更後，自動訓練、單元測試、模型驗證與基準比較。提早發現問題、降低人為錯誤。
CD模型通過品質門檻後，自動部署到測試或生產環境。加快交付並一致化流程。
Model Versioning追蹤資料、程式、參數、模型、指標與環境。可追溯、可重現、可回退。
A/B／Blue-Green以受控流量比較或切換新舊版本。降低正式上線風險。
MLflow實驗追蹤、模型管理、部署與版本管理。管理 ML 生命週期。
DVC資料集與模型版本追蹤。讓資料／模型與程式版本對齊。

5.1 上線後監控與更新

監控資料、模型、服務與資源
異常偵測漂移、錯誤、延遲
觸發門檻例：準確率下降 5%
再訓練更新資料與標註
模型驗證技術、風險與業務門檻
安全部署Rolling／Hot Swap
持續改善回饋進入下一輪

Prometheus + Grafana

Prometheus 收集指標，Grafana 建立 Dashboard；搭配 Alert 在門檻越界時通知維運人員。

監控四類訊號

Data Drift、Model Drift、準確率／錯誤率／延遲／吞吐量，以及 CPU、GPU、記憶體與服務狀態。

官方 P. 5-21～5-22
部門／角色主要責任

協作閉環

需求共同定義 → 成效共同衡量 → 問題共同處理 → 成果共同負責

制度上需有定期工作小組、共同 KPI、快速決策通道與跨部門 AI 培訓。

08｜易混淆辨析與 iSpan 題型

整合複習
主題常見誤判正確辨析
Docker vs Kubernetes兩者都是用來建立容器。Docker封裝與執行容器；Kubernetes編排大量容器、調度、擴縮與恢復。
公有雲 vs 私有雲私有雲一定比較便宜。私有雲控制高但建置維運昂貴；公有雲彈性高但需評估資料主權、成本與鎖定。
CI vs CDCI 就是把模型部署上線。CI整合與驗證變更；CD把通過門檻的版本交付／部署。
Rolling vs Blue-Green都是瞬間把所有流量切到新版本。Rolling逐批換節點；Blue-Green維持兩套環境後切流量。
Model Drift vs Data Drift兩者完全相同。Data Drift是輸入分布改變；Model Drift是預測表現或分布惡化。
技術成功 vs 業務成功AUC／Accuracy 高就算導入成功。還要看 CTR、轉換率、成本、留存、ROI 與流程採用。

115-1 MLOps 核心角色

建立機器學習流程自動化與版本管理，支援訓練、測試、部署、監控、再訓練與持續更新；不是只做標註或 AutoML。

115-1 影像 API 上傳

高解析影像宜用 HTTP POST，以 multipart/form-data 或 application/octet-stream 放在 Request Body；不應把大型 Base64 放進 GET URL。

115-1 外部服務連鎖故障

外部 API 偶發逾時造成 Cascading Failure，應導入 Circuit Breaker，異常時暫停呼叫、快速失敗並提供替代回應。

官方題型 邊緣推論

Edge Computing 的推論發生在手機、攝影機、IoT 等終端裝置本地端，以降低延遲與頻寬。
